OpenAI が「GPT-6 系モデルは推論とコードだけで protein を設計できる」とする preprint を公開、実験で 10.9% が結合

11/24 公開。protein 専用に作ったモデルではなく、汎用の GPT-6 系モデルが推論とコード実行だけで minibinder(標的に結合する小さな protein)の構造と配列を設計したという報告。実験パートナー Onava による評価で、5つの標的に対して作った 322 個のうち 35 個(10.9%)に結合の兆候が見られ、どの標的にも最低1つは当たりが出た。内訳は IL-17A 18件、VEGF-A 8件、PD-L1 5件、IL-7Rα 3件、TrkA 1件。別の実験では、GPT-6.2 自身が生成した未公開構造から新しい配列を起こし、107 個のうち 14 個(13.1%)が結合した。
注意点も多い。査読前の preprint であり、候補の絞り込みには Boltz-2・OpenDDE・ESMFold2 といった専用の構造予測モデルを使っている。OpenAI 自身も「専用モデルの助けなしに end-to-end・zero-shot で de novo minibinder を作れることを示したわけではない」としている。汎用モデルが領域特化モデルの仕事をどこまで肩代わりできるかの指標として見る価値がある。
この環境からは openai.com に直接接続できないため、内容は検索結果と報道で確認した(報道ベース)。

Claude Code v2.1.332 — MCP サーバーの skill が / メニューに、PreSkillShellCommand hook 追加、モデル別名の指す先が変更

11/25 公開。MCP サーバーが提供する skill が / メニューに server:skill の形で並ぶようになった(beta)。skill やコマンドが読み込まれる際のインラインシェルコマンドを拒否できる PreSkillShellCommand hook も追加された。他セッションからの保留メッセージに「Always deliver」が付き、セッションが別モデルのときはフッターに警告が出る。
設定の確認が必要な変更がある。Bedrock Mantle の sonnet 別名は Haiku 4.5 から Sonnet 5 に、Google Cloud Agent Platform と Microsoft Foundry の sonnet は Sonnet 5.5 に、Foundry の opus は Opus 5.5 を指すようになった(Bedrock の sonnet は Sonnet 4.5 のまま)。Foundry の既定モデルは Sonnet 5.5 で、claude-sonnet-5-5 を deploy するか ANTHROPIC_DEFAULT_SONNET_MODEL を設定する。デスクトップ Code タブの OpenTelemetry service.name は claude-code-desktop に変わったので、claude-code で絞っているフィルタは直す。自己ホスト runner のトークンは oat02- 接頭辞も取り得る。
修正面では、Read・@メンション・compaction が named pipe で固まる問題、出力が止まらない hook、SSE MCP サーバーの再接続後にツール呼び出しが通らない問題などが直った。claude auth login はログイン情報を保存できなかったときに成功と言わず exit 1 するようになった。
